# 跨平台播放兼容性修复与案例重导出 —— 操作记录

- 记录时间：2026-09-29 13:25
- 触发问题：`output/` 的成片在安卓平板默认播放器报「格式不支持 / 视频无法播放」，
  而同片源的 `input/` 文件可正常播放
- 结论：与分辨率 / 码率 / 帧率无关，坏在**编码层三个参数**（见下文「根因」）
- 相关提交：`ac74bdb`（代码 + 文档 + 测试）、`c7cd667`（案例成片更新，走 LFS）

---

## 1. 根因

| 项 | `input/`（能播） | 旧成片（不能播） | 移动端要求 |
| --- | --- | --- | --- |
| 视频编码 / tag | h264 `avc1` | hevc `hev1` | H.264 必支持；HEVC 必须 `hvc1` |
| Profile | High | **Rext** | 只保证 Main / High（8bit） |
| 像素格式 | `yuv420p` | **`yuv444p`** | 只保证 4:2:0 / 8bit |
| 分辨率 / 帧率 / 码率 / 音频 | 712×400 / 25fps / 650k / aac | 1424×800 / 25fps / 723k / aac | 均合规，**不是原因** |

1. **4:4:4 泄漏**：RVE 只在 `tools/backend/src/FFmpegBuffers.py` 的
   `custom_encoder is None` 分支自补 `-pix_fmt`；流水线为限制 x264 线程内存传了
   `--custom_encoder`，RVE 便不再补，rawvideo `rgb24` 被自动协商成 `yuv444p`，
   中间产物变 `H.264 High 4:4:4 Predictive` 并一路继承到成片。
2. **`hev1` tag**：ffmpeg 对 MP4 里的 HEVC 默认写 `hev1`（参数集在码流内），
   硬件解码器普遍只认 `hvc1`（参数集在 `hvcC`）。
3. **整体换成了 HEVC**：老款/低端机型无 HEVC 解码器。

命中范围（扫 `logs/jobs/*.log` 的 `FFMPEG WRITE COMMAND`）：
52 次 RVE 调用中有 **3 次**缺输出 `-pix_fmt` → 录像04(job 10)、录像06(job 12)、
S01E04_seg30min(job 45)，均产出 `yuv444p` 中间产物。

## 2. 关键操作步骤与结果

| # | 操作 | 结果 |
| --- | --- | --- |
| 1 | `ffprobe` 逐项对比 input / output 的视频、音频、容器参数 | 锁定 profile / pix_fmt / tag 三项不兼容 |
| 2 | 扫 `logs/jobs/*.log` 统计 RVE 写入命令 | 3/52 缺 `-pix_fmt`，定位到 `--custom_encoder` 分支 |
| 3 | 备份缺陷成片为 `S01E04_seg30min.orig-hev1-444.mp4`（后改名 `.bak`） | 可回退 |
| 4 | 重编码补救（不重跑 AI）：`libx264 -preset medium -crf 18 -profile:v high -pix_fmt yuv420p -c:a copy -movflags +faststart` | 用时约 6 分钟（170 fps，6.8x 实时） |
| 5 | `ffprobe` 断言新产物 | h264 / High / yuv420p / avc1 / aac LC 48000 |
| 6 | `ffmpeg -v error -i ... -f null -` 完整解码 | rc=0，零报错 |
| 7 | 检查 moov 位置 | offset 36，faststart 生效 |
| 8 | 交付实机验证 | 用户确认安卓默认播放器可正常播放 |
